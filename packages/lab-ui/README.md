# @unilab/lab-ui

面向实验室业务场景的可选 UI 组件包。它服务于用户端和开发者端的共同业务界面，组件以领域模型或场景视图模型作为输入，以稳定的业务意图回调作为输出。

## 当前状态

本包已经完成第一批只读/受控业务组件：物料列表、库位选择、物料事实检查、设备状态和动作列表、设备动作参数输入、试剂库存/目录摘要、目录详情、库存历史、工作流输入、库存需求、运行前检查、运行准备摘要和提交前确认。设备与试剂中的稳定展示已经在 developer-web 使用，物料库位选择也已接入并保留原页面视觉变体。

组件迁移遵循“先验证页面，再扩大复用”的节奏。列表查询、分页、能力判断和写入命令仍属于应用场景，组件本身不持有这些状态。

任务列表、任务详情、任务时间线和调试工具栏仍在产品设计中的内容继续由应用自行组合，避免在领域和交互尚未稳定时形成公共 API。设备调试命令、试剂写入表单、资源候选到 OS 命令的绑定也保留在应用层，直到统一命令契约和 capability 语义冻结。

## 依赖边界

允许的依赖方向：

```text
@unilab/lab-ui -> @unilab-fe/core
@unilab/lab-ui -> @unilab/design-v2
```

组件不得直接依赖 `@unilab/services`、`@unilab/material`、`@unilab/workflow-editor` 或任何应用包。数据读取、命令提交、权限和 profile 差异由应用通过 `core` 的 port 和场景组装后传入；组件不直接请求接口、访问路由或持有业务 store。

## 组件契约

- 输入优先使用 `core` 的 domain model、view model 和 capability。
- 输出使用稳定的业务 intent，例如选择物料、选择库位、提交运行准备、打开任务。
- 组件不复制领域实体，不拥有跨组件事实，不按 backend 或 profile 分支。
- 视觉基础来自 `design-v2`；业务组件可以组合视觉 primitive，但不在这里重新定义设计 token。

## 预留业务域

- `src/material/`：物料、库位及其关系的业务展示和选择。
- `src/workflow/`：工作流版本、输入、资源绑定和执行前预览。
- `src/run/`：运行准备摘要、约束和提交前确认。
- `src/task/`：任务列表、状态和节点时间线。
- `src/shared/`：跨业务域的语义组件和交互契约。

组件只有在领域模型稳定、至少两个场景需要、并且能通过 props 和 intent 回调保持应用无关时，才进入这些目录。
