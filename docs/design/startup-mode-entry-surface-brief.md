# 启动模式入口视觉简报

## 视觉权威与范围

- 原型文件 [experiment-debug-platform.html](../../../.whalent_tmp/2026-08-26/uy4cq2cc6ls1whfgpzf5ch5va-experiment-debug-platform.html) 是本入口的视觉权威；实现应优先复现其层级、色彩、密度和响应式关系。
- 仅适用于 Electron 初始化欢迎页，以及 Theia 的退出模式／会话入口。不得扩散到设备、物料、工作流、任务等操作工作台。
- 此入口不包含登录，也不承载各业务模块的详细配置。

## 入口任务

入口只完成两项选择：

1. 选择调试模式或生产模式。
2. 选择当前设备包工作区。

Runtime／OS 启动能力继续保留；仿真、真实设备、生产 Backend、Scheduler 等配置在进入工作台后复用现有配置弹窗处理，不在入口重复实现。

## 视觉方向

- 桌面采用左右分屏：左侧为深蓝工业控制面，右侧为浅灰网格工作区与白色模式卡。
- 左侧承载 Uni-Lab Studio 品牌、运行控制台标题和三层能力说明；强调冷静、精密、工业控制感。
- 右侧模式卡是唯一主操作面，依靠清晰边界、紧凑字段和单一进入按钮建立操作顺序。
- 窄屏隐藏左侧品牌面，模式卡改为单列并占据主要视口；不得产生横向滚动或压缩到不可读。

## 根设计规范的局部例外

本入口是根 [DESIGN.md](../../DESIGN.md) 中以下规则的入口级例外：

- **No Hero Type**：允许左侧使用大标题建立启动识别，但标题不得进入实际操作工作台。
- **Flat-at-Rest**：允许白色模式卡使用克制阴影，以表达其浮于启动背景之上的入口层级；工作台静止表面仍须保持扁平。

除上述明确例外外，继续遵守根设计规范的术语、可访问性、焦点、语义色和响应式要求。

## 状态与数据完整性

- 工作区、Runtime／OS、服务状态和错误信息必须来自真实桌面 API 或现有会话接口。
- 禁止将原型中的示例路径、在线状态、设备包、环境名或其他演示常量写入产品逻辑。
- 未确认、检查中、失败和可用状态必须以真实结果呈现；颜色只能辅助文字和结构，不能单独作为状态证据。
